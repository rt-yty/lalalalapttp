# Исправление поиска концертов — 28 октября 2026

Последующее изменение сценария: перед подбором поездки теперь обязательно уточняются пожелания пользователя; подробности и новые проверки в `CONCERT_INTAKE_REPORT.md`. Описанный ниже живой прогон относится к исследованию расписания до добавления этого этапа.

Исходный запрос пользователя: «Хочу на концерт Маргенштерна». До исправления поиск сводился к одному выступлению в Хайфе в день запроса и задавал вопрос о выборе из нескольких вариантов.

## Проверенный результат

Полный повтор через настоящий поиск, чтение страниц и настоящую модель вернул **шесть будущих концертов в шести городах**. Это не подстановка записанной выдачи и не фиксированный ответ про артиста.

| Дата | Город | Площадка |
|---|---|---|
| 31.10.2026 | Вильнюс | Pramogų arena |
| 02.11.2026 | Братислава | Majestic Music Club |
| 03.11.2026 | Кёльн | Carlswerk Victoria |
| 05.11.2026 | Мюнхен | Backstage Kulturzentrum |
| 09.11.2026 | Токио | duo MUSIC EXCHANGE |
| 11.11.2026 | Сеул | MH LIVE HALL |

Основание: прочитанное [расписание организатора World Tour 2026 Part 2](https://readyevents.eu/morgenshtern-tour/?l=ru). Год указан в заголовке тура, строки расписания содержат даты, города и площадки. Выступление 28 октября в Хайфе исключено из обычного планирования поездки. Наличие концертных билетов не проверялось и не заявлялось.

Артефакт `concert-live-final.json` содержит полный ответ, события поиска и последующий выбор концерта в Сеуле. Выбор сохранил город и дату 11.11.2026; следующий вопрос — «Из какого города поедете?». Даты поездки не выдумывались. `concert-extraction-context.json` и `concert-extraction-raw.json` сохраняют использованные общедоступные страницы и результат извлечения. После последнего ужесточения проверки года эта же реальная выдача повторно прошла валидацию: все шесть событий сохранены.

## Причины и исправления

| Найденная проблема | Исправление |
|---|---|
| Короткая поисковая выдержка с одной ближайшей датой считалась достаточной | Для событий исследуется календарь тура: до двух уточняющих запросов, до 16 разных источников, до шести прочитанных страниц; запас времени на ответ сохраняется. |
| Архивные страницы одного домена занимали бюджет чтения, хотя в исходной выдаче был полный календарь | Приоритет расписаниям и датам тура; сначала разные домены, затем дополнительные страницы. Повторы URL и запросов исключаются. |
| Модель отбрасывала таблицу с датами `31/10`, поскольку год был только в заголовке | Явный заголовок тура применяется к строкам под ним; вертикальные таблицы поддерживаются. Проверка не добавляет выдуманный год к цитате. |
| Год в футере мог ошибочно подтверждать дату | Принимается год непосредственно у даты либо ближайший однозначный предшествующий заголовок расписания. Футер, конфликтующий год и диапазон 2026/2027 без принадлежности строки не подходят. |
| Сегодняшний концерт навязывался как основа поездки | По умолчанию принимаются даты начиная с завтра. Сегодня допустимо только по явной просьбе пользователя. |
| Единственный вариант сопровождался вопросом о множественном выборе | Для одного результата говорится об одной подтверждённой дате и предлагается продолжить поиск. Для нескольких выводится список. |
| Даты существовали только в тексте ответа | Добавлены структурированные карточки, версия списка и действие `select_event`; устаревший выбор отклоняется. Город и дата выбранного события сохраняются отдельно от дат дороги. |
| «Другие?» не всегда запускало новое исследование | Несколько формулировок запускают поиск других дат и городов. Повторные события не выдаются за новые; если новых подтверждений нет, прежний список сохраняется с честным сообщением. |
| Новый артист мог оставить карточки старого при ошибке поиска | При смене предмета исследования старый список и выбранное событие сбрасываются. |
| Модель могла вывести смещение часового пояса из города | Время с поясом сохраняется только при подтверждённом времени и явном часовом поясе в источнике. Иначе остаётся только подтверждённая дата. |
| Кратковременный лимит поиска прерывал цепочку | Один ограниченный повтор начального поиска, последовательные уточнения и пятиминутный кэш успешных запросов. `Retry-After` учитывается в безопасных пределах. HTTP 429 сам по себе не объявляется суточной квотой. |
| Первый выбор концерта стирал явно заданный подходящий интервал поездки | Первый выбор сохраняет указанные даты. Смена уже выбранного события сбрасывает даты для повторного согласования. |
| Поездка целиком до или после события могла уйти во внешний поиск; отель без транспорта проходил все проверки | Противоречие дат вызывает один вопрос до обращения за предложениями. Для отеля добавлена обязательная проверка даты события. Выезд в день концерта требует явного подтверждения, что пользователь останется в городе после выезда; подтверждение связано с конкретным маршрутом и интервалом. |
| Страна из карточки неоднозначного города терялась при выборе | Для известных неоднозначных названий город отправляется в поиск вместе с подтверждённой страной. Повторный вопрос о стране не задаётся; выбранное событие сохраняется. Названия шести городов живой проверки не меняются. |

## Проверки

Целевой набор: `test_event_choices.py`, `test_web_research.py`, `test_search_yandex.py`, `test_suggestions.py` — **173 passed**. Проверены несколько дат, один результат, отсутствие подтверждений, сегодняшние и прошлые события, неизвестные источники, выдуманные цитаты, неверные годы и футеры, заголовки тура, часовые пояса, сохранение выбора, устаревшие действия, смена артиста, запрос других дат, продолжение обычной темы путешествия, разнообразие страниц, кэш и ограничение запросов. Финальный общий прогон всех модулей и браузерная проверка отражаются в общем отчёте проекта.

Дополнительный интеграционный аудит обнаружил две ошибки согласования дат, перечисленные выше, и потерю страны неоднозначного города. После исправлений `test_event_choices.py`, `test_state_sequences.py`, `test_suggestion_audit_regressions.py` прошли заново: **138 passed**. Проверены сохранение первого интервала, смена события, четыре вида набора услуг с датами до/после концерта, ответы «да» и «нет» на выезд в день концерта, устаревшее подтверждение после смены маршрута, смена артиста после выбора события и сохранение известной страны для неоднозначного города. Исправление фронтендом явного `selected_event: null` и целостного восстановления снимка отражается в браузерном аудите.

`concert-fix-live-first.json` сохраняет первую реальную неудачу с ограничением запросов. Во время исследования также воспроизведено извлечение пустого списка из реального календаря: оно помогло найти проблему с годом в заголовке. Отдельный `concert-live-context-reextract.json` проверяет настоящую модель на уже записанном контексте и не считается полным живым поиском. Более ранний `concert-recorded-pages-result.json` с семью событиями — тоже отдельная проверка записанных страниц. Итогом полного живого поиска считаются именно **шесть** событий из `concert-live-final.json`.

Открытых воспроизведённых дефектов в этом наборе нет. Источники могут менять расписание; проверка конкретного артиста не доказывает полноту всех мировых афиш. Предел в 12 проверенных карточек ограничивает размер одного ответа, а не останавливает исследование после первого события.
