# Запуск бэкенда

FastAPI обслуживает API и собранный React из `frontend/dist`. Состояния поездок,
история, заказы, задания и явно сохранённые предпочтения хранятся в Postgres.
SQLite сохранён для автономного запуска и быстрых тестов. Redis не требуется:
для демо достаточно трёх одновременно исполняемых запросов и устойчивого
журнала заданий в основной базе.

## Локальный запуск с настоящей моделью

```sh
cd frontend && npm ci && npm run build && cd ..
uv sync --locked
DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:5432/travel uv run uvicorn travel_agent.asgi:app --host 127.0.0.1 --port 8765
```

Настройки `AGENT_MODEL_BACKEND=codex` используют установленный и авторизованный
Codex CLI на хосте. Не передавайте его учётные данные в исходный код или образ.
Для Postgres создайте отдельную базу и пользователя; схему создаёт приложение
при старте. API health: `GET /api/health`.

## Контейнеры

```sh
docker compose up --build
```

Эта команда запускает воспроизводимый офлайн-режим rules/replay с имитацией
оформления; цены из архива явно отмечены в интерфейсе. Codex CLI в образ не
включён. Для модели внутри контейнера используйте `COMPOSE_MODEL_BACKEND=hf`,
`HF_TOKEN`, `HF_MODEL_ID` и поддерживаемый gateway-провайдер; для живого поиска
установите `COMPOSE_DATA_MODE=live`. Это отдельные режимы; живой поиск никогда
не подменяется архивом при сбое. Образ не содержит `.env`, историю и секреты.

Порт по умолчанию доступен только локально. Для внешнего развёртывания нужен
HTTPS reverse proxy, `COOKIE_SECURE=true`, фактическое имя в `ALLOWED_HOSTS`
и отдельный стойкий `POSTGRES_PASSWORD`. Не публикуйте порт Postgres. Настройка
поисковых ключей через браузер выключена; задавайте их переменными окружения.

Запускайте **один процесс приложения**. Postgres advisory lock предотвращает
одновременный запуск второго сервера на той же базе, чтобы перезапуск не
помечал ещё исполняемые задания соседнего процесса как прерванные. При остановке
сохраняются завершённые ходы; прерванный ход получает понятную ошибку после
перезапуска. Точный повтор выполненного запроса возвращает прежний результат.
Транзакции Postgres отдельно защищают версию, повтор и создание демозаказа.
Временные checkpoints графа не являются источником сохранённой поездки.

## Сборка поставки

Сначала соберите React, затем выполните `uv build`. Wheel содержит готовый
интерфейс, четыре агентских skill-файла и архивный пример; он запускается
и вне рабочей папки проекта. Source archive также содержит исходники React,
конфигурацию и сценарии запуска. Данные поездок, `.env` и `node_modules`
в поставку не входят. Без собранного `frontend/dist` упаковка намеренно
завершается ошибкой, чтобы не выпустить старый интерфейс.

## Клиентский контракт

1. `GET /api/bootstrap` устанавливает HttpOnly cookie посетителя и отдаёт
   `csrf_token`. Сохраняйте cookie, передавайте токен в `X-Travel-Token` при
   POST/PATCH. Все запросы идут с того же origin.
2. `POST /api/turns` принимает существующий `WebTurn`, возвращает HTTP 202
   и `job_id`. `GET /api/jobs/{job_id}` возвращает статус, события и результат.
3. `GET /api/sessions/{session_id}` восстанавливает состояние и сообщения.
   `GET /api/sessions` возвращает список последних поездок этого посетителя.
4. `GET /api/profile`, `PATCH /api/profile` читают и явно сохраняют
   `{origin: string, preferences: string[]}`. Явно сохранённый город служит
   отправной точкой новой поездки; текущий запрос может его заменить.
   Предпочтения передаются модели как мягкие пожелания и не меняют уже
   начатую поездку.

Для работы обязателен аккаунт по email/паролю. Без входа доступны только начальная
загрузка приложения, регистрация, вход и проверка работоспособности. После входа поездки
и профиль доступны с других устройств; гостевые данные прежних версий переносятся атомарно.
Контракт регистрации, входа, выхода, сроков cookie и защиты описан в [AUTH.md](AUTH.md).
Создавать новые гостевые поездки нельзя. Сохранённая cookie прежней версии может использоваться только для переноса старых данных при входе.
Идентификатор поездки сам по себе не даёт доступа чужому посетителю. Старая общая история
`local-web` сохраняется в базе как архив и автоматически никому не присваивается.

## Проверка PostgreSQL

```sh
TEST_POSTGRES_URL=postgresql://USER:PASSWORD@127.0.0.1:5432/travel_test uv run pytest -q tests/test_postgres.py
```

Тесты создают временную уникальную схему и удаляют только её. Используйте
отдельную тестовую базу. Полный образ требует Docker, а локальные интеграционные
тесты используют непосредственно установленный PostgreSQL.
